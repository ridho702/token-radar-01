How this radar works

Value model. A log-log regression fitted on the 144 token-bearing protocols in this snapshot: log(market cap) = intercept + slope × log(TVL), then a small second-stage adjustment for 7-day growth and protocol age (both coefficients halved, total adjustment clamped to ±0.35 log points). The second stage's intercept is not applied — it is a mean offset of the fitting subset, not a signal. The model uses a pooled intercept: category-specific intercepts were also fitted, but rejected — they won held-out data by only ~3% (mean median |log error| 1.080 vs 1.114) and lost walk-forward (1.258 vs 1.214), so the pooled model is used. The resulting values are the radar's own claim, not a prediction that a token will launch.

Odds. A protocol's chance of launching a token is estimated from its peers: its category's token rate, shrunk toward the 19% global rate, times an age-band factor (young protocols launch far less often), clamped to 2–50%.

Expected value. Implied value = fitted fair value × odds. It is the radar's own claim about what a token would be worth if one launched and the protocol's record stayed as it is — not a prediction that one will launch, or when.

Farm plans. Six concrete steps per protocol, in English, with amounts per tier (Small $100 / Medium $1,000 / Large $10,000), gas and time. Gas is a planning estimate, not a live quote.

Integrity strip

A pre-token protocol is left off this board when another protocol with the same brand stem already has a token trading (stem = slug minus a trailing version suffix, first segment).
